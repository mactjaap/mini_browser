Mini Browser 2.5

Mini Browser is a compact, interactive, text-oriented web browser for the WHY2025 badge, written in C using SDL3 and libcurl.

Version 2.5 builds on the 2.4 Unicode and rendering foundation with a more robust HTML/entity parser, editable action-number input, bounded POST form submission, a bounded in-memory cookie jar and a WHY+I HTTP/TLS Inspector. It retains the 56,352-glyph Unicode font, word-aware wrapping, RTL/Bidi rendering, contextual Arabic shaping, bookmarks, history and complete-page screenshots.

Unicode and UTF-8




ASCII uses the built-in bitmap font. Additional Unicode characters can be loaded from
APPS:[mini_browser]unifont_cjk.bin. The tested 2.4 generated font contains 56,352
usable glyphs across 101 ranges selected from GNU Unifont 17.0.02 Plane-0 and
supplementary-plane sources. The MBCJ v1 range table is read from the file header
at runtime rather than being hard-coded in the browser source.





Coverage includes broad Latin extensions (including Icelandic), Greek, Cyrillic,
Armenian, Hebrew, Arabic and Arabic presentation forms, Indic scripts, Thai, Lao,
Tibetan, Georgian, Ethiopic, Cherokee, Runic, Hangul/Korean, Hiragana, Katakana,
Bopomofo, CJK Extension A, CJK ideographs, Yi, punctuation, currency, mathematical
and technical symbols, fullwidth forms and supplementary symbol/emoji ranges.





Wrapping is UTF-8 safe, pixel aware and word aware. Complete words stay together
where possible. CJK text and overlong unbroken tokens fall back to UTF-8-safe
glyph-level wrapping. ASCII and 16x16 Unicode glyphs have different rendered widths,
and Mini Browser accounts for that when laying out lines.





If the external Unicode font is not installed, the built-in ASCII renderer remains
available. Unordered lists intentionally use the ASCII * marker rather than requiring
a Unicode bullet.







RTL/Bidi and Arabic shaping




Mini Browser 2.4 renders Hebrew and Arabic right-to-left and supports mixed LTR/RTL
lines. Arabic letters are contextually shaped into their joining forms using glyphs
included in the 2.4 Unicode font.





The implementation is deliberately compact for BadgeVMS and is not a claim of complete
support for every Unicode Bidirectional Algorithm control or every complex-script
shaping rule.







Real bold text




HTML b and strong elements are rendered as genuinely bold text. Mini Browser no longer
shows literal ** markers for these elements. Bold is produced by an additional
one-pixel horizontal glyph pass and works for both ASCII and Unicode glyphs.







Monochrome emoji




Many single-codepoint Plane-1 emoji can be rendered from the external GNU Unifont
bitmap file, for example: 😀 😃 😂 😎 🤖 👍 🐶 🍕 🚀 🌍 💡 💻





These are monochrome bitmap glyphs, not color emoji. Complex ZWJ sequences, skin-tone
composition, gender sequences and regional-indicator flag composition are not
implemented. Variation-selector handling is limited.







Simple HTML forms




Mini Browser supports simple GET and POST forms. Supported input types include text, search,
url, hidden and submit. Submit buttons made with the button element are also supported.




[1] q:
[2] [Search]





Type 1 and press Enter to edit the field. Enter the search text and press Enter again
to store it. Then type 2 and press Enter to submit.





GET and POST form data is URL encoded as application/x-www-form-urlencoded. Hidden
fields are submitted, disabled fields are ignored, and an activated named submit button
is included where appropriate. POST request bodies are bounded to 2048 bytes. Up to 4
forms with up to 8 fields per form are supported.





Textarea, select, checkboxes, radio buttons, file uploads and JavaScript-driven forms
are not currently supported.

Navigation




Links and visible form controls receive action numbers. Type an action number and press
Enter to activate it.





Use Up and Down to scroll; holding an arrow gives continuous scrolling. J and K provide
one-line scrolling.

Screenshots




Mini Browser 2.4 supports two screenshot modes. WHY+S captures the visible 716x716
browser viewport. WHY+Z captures the complete rendered page, including content below
the viewport. Full-page capture reuses the normal renderer as a slice-based scratch
surface, so it does not allocate a giant 716xN framebuffer or change the current
scroll position.

Both modes use RGB24 data from the SDL renderer, lightweight RLE5 compression,
per-record CRC32 and XOR forward-error correction, transmitted over USB serial.





The Mini Browser repository includes the standalone receiver badge_screenshot.py.
Start it on a serial-connected macOS or Linux computer and then press WHY+S on the badge:




./badge_screenshot.py /dev/cu.wchusbserial10




For a complete rendered page:



./badge_screenshot.py /dev/cu.wchusbserial10 --full-page





On Linux the device will commonly be something such as /dev/ttyUSB0. The receiver
validates the transfer, repairs a single missing or damaged data record per FEC group
where possible, verifies the complete CRC32, decodes the RLE stream and writes a PNG.





A custom firmware is not required for screenshots triggered physically with WHY+S.
The screenshot-enabled Mini Browser and a USB serial connection are sufficient.





The receiver can also request the screenshot from the host:




./badge_screenshot.py /dev/cu.wchusbserial10 --request
./badge_screenshot.py /dev/cu.wchusbserial10 --full-page --request





The --request mode requires the custom firmware because stock BadgeVMS firmware does
not implement the host-to-badge serial keyboard protocol.







Optional custom firmware and automated testing




A customized WHY2025 firmware is available at
github.com/mactjaap/firmware.
It adds a serial keyboard bridge to the normal BadgeVMS keyboard path, allowing a
macOS/Linux computer to send keyboard events to Mini Browser over USB serial.





The firmware repository includes badge_keyboard.py for interactive computer-keyboard
control of the badge. This also allows browser accelerator commands such as WHY+E,
WHY+H, WHY+R, WHY+B, WHY+G, WHY+F, WHY+S, WHY+Z and WHY+Q to be generated remotely.





The same repository contains automated Mini Browser test scripts. They can drive
navigation, open configured websites, perform searches, exercise browser commands and
automatically request and save screenshots after test steps. This provides repeatable
regression testing without manually operating the badge for every page.





The custom firmware is optional for normal Mini Browser use and physical WHY+S
screenshots. It is required when a host must send keyboard commands to the badge,
including fully automated tests and badge_screenshot.py --request.







Opening URLs from macOS or Linux




The repository includes badge_open_url.py, a small host-side tool for sending
URLs directly to Mini Browser over the custom firmware's serial keyboard bridge. This
is useful for testing because URLs can be pasted on the computer instead of being typed
manually on the badge.




The script requires Python 3 and pyserial:



python3 -m pip install pyserial




To paste a URL interactively:



./badge_open_url.py





Paste the URL at the prompt and press Enter. The script sends WHY+E, enters the URL
through the normal BadgeVMS keyboard path and presses Enter.




A URL can also be supplied directly:



./badge_open_url.py https://example.com/




To open the URL currently on the macOS or Linux clipboard:



./badge_open_url.py --clipboard





The script can also run a list of URLs as a simple Mini Browser presentation. Put one
URL per line in a text file. Blank lines and lines beginning with # are ignored.




For example, urls.txt:



# Mini Browser demonstration
https://example.com/
https://news.ycombinator.com/
https://wiby.me/




Run the presentation with:



./badge_open_url.py -f urls.txt





Each page is displayed for 30 seconds by default. Change the interval with -s:




./badge_open_url.py -f urls.txt -s 10





Use -z to request a complete WHY+Z screenshot of every page in the list:




./badge_open_url.py -f urls.txt -z





This combines the URL presentation with badge_screenshot.py --full-page --request.
The screenshot receiver can be specified explicitly:




./badge_open_url.py -f urls.txt -z --screenshot-script ./badge_screenshot.py





When badge_screenshot.py is in the same directory as badge_open_url.py, it is normally
found automatically. Screenshots are written through the screenshot receiver; the
presentation script uses a screenshots directory by default.




A useful automated demonstration and screenshot run is therefore:



./badge_open_url.py -f urls.txt -s 15 -z





The script auto-detects common macOS and Linux serial devices. A device can also be
selected explicitly:




./badge_open_url.py --device /dev/cu.wchusbserial10 https://example.com/





On Linux the device will commonly be something such as /dev/ttyUSB0 or /dev/ttyACM0.





Because URL entry and host-requested screenshots use the serial keyboard bridge,
badge_open_url.py requires the customized WHY2025 firmware described above.







HTTP/TLS Inspector




Press WHY+I to open the HTTP/TLS Inspector for the current page. It shows bounded
metadata retained from the actual request without making an extra HEAD request: page
title and size, link/form/action counts, request method and URL, transport, cookies
sent, HTTP status and Content-Type, cookie-jar usage and browser limits.





The trimmed BadgeVMS libcurl exposes only a small set of CURLINFO fields. Connection
address/port, negotiated HTTP version, certificate details and certificate-verification
result are therefore reported as unavailable rather than guessed. Effective/final URL
and redirect metadata are also reported as unavailable because they are not reliable in
this environment. WHY+B or WHY+I returns to the page.







Cookies




Mini Browser 2.5 includes a bounded in-memory session cookie jar. It stores up to 12
cookies, supports replacement, path scoping and deletion with Max-Age=0, and sends
matching cookies on subsequent requests. Cookies are not persisted across browser
restarts.







Bookmarks and history




Mini Browser stores up to 32 bookmarks and maintains up to 32 HTTP/HTTPS history
entries. Going Back and then navigating somewhere new discards the old forward branch.
Reloading does not create a duplicate history entry.




APPS:[mini_browser]bookmarks.txt







Network behaviour




Mini Browser uses libcurl and HTTP/1.1 where available, follows redirects to a bounded
limit and requests identity transfer encoding. Connection failures and HTTP errors are
shown as readable browser pages.

Unsupported web features




Mini Browser does not implement JavaScript, CSS layout, images, audio/video, complex
form controls, file uploads, a complete HTML5 DOM/parser, color
emoji or complex emoji composition.







Unicode font




The tested 2.4 font asset combines unifont_jp-17.0.02.hex and
unifont_upper-17.0.02.hex into unifont_cjk.bin. The generated MBCJ v1 file contains
56,352 usable glyphs across 101 ranges and is 1,804,488 bytes (about 1.72 MiB). GNU Unifont is dual-licensed under the
