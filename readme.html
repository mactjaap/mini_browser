Mini Browser 2.4

Mini Browser is a compact, interactive, text-oriented web browser for the WHY2025 badge, written in C using SDL3 and libcurl.

Version 2.4 combines links, GET forms, bookmarks and Back/Forward history with 56,352-glyph Unicode rendering, word-aware UTF-8-safe pixel wrapping, RTL/Bidi rendering, contextual Arabic shaping, monochrome Plane-1 emoji and genuine bold text.

Unicode and UTF-8

ASCII uses the built-in bitmap font. Additional Unicode characters can be loaded from APPS:[mini_browser]unifont_cjk.bin. The tested 2.4 generated font contains 56,352 usable glyphs across 101 ranges selected from GNU Unifont 17.0.02 Plane-0 and supplementary-plane sources. The MBCJ v1 range table is read from the file header at runtime rather than being hard-coded in the browser source.

Coverage includes broad Latin extensions (including Icelandic), Greek, Cyrillic, Armenian, Hebrew, Arabic and Arabic presentation forms, Indic scripts, Thai, Lao, Tibetan, Georgian, Ethiopic, Cherokee, Runic, Hangul/Korean, Hiragana, Katakana, Bopomofo, CJK Extension A, CJK ideographs, Yi, punctuation, currency, mathematical and technical symbols, fullwidth forms and supplementary symbol/emoji ranges.

Wrapping is UTF-8 safe, pixel aware and word aware. Complete words stay together where possible. CJK text and overlong unbroken tokens fall back to UTF-8-safe glyph-level wrapping. ASCII and 16x16 Unicode glyphs have different rendered widths, and Mini Browser accounts for that when laying out lines.

If the external Unicode font is not installed, the built-in ASCII renderer remains available. Unordered lists intentionally use the ASCII * marker rather than requiring a Unicode bullet.

RTL/Bidi and Arabic shaping

Mini Browser 2.4 renders Hebrew and Arabic right-to-left and supports mixed LTR/RTL lines. Arabic letters are contextually shaped into their joining forms using glyphs included in the 2.4 Unicode font.

The implementation is deliberately compact for BadgeVMS and is not a claim of complete support for every Unicode Bidirectional Algorithm control or every complex-script shaping rule.

Real bold text

HTML b and strong elements are rendered as genuinely bold text. Mini Browser no longer shows literal ** markers for these elements. Bold is produced by an additional one-pixel horizontal glyph pass and works for both ASCII and Unicode glyphs.

Many single-codepoint Plane-1 emoji can be rendered from the external GNU Unifont bitmap file, for example: 😀 😃 😂 😎 🤖 👍 🐶 🍕 🚀 🌍 💡 💻

These are monochrome bitmap glyphs, not color emoji. Complex ZWJ sequences, skin-tone composition, gender sequences and regional-indicator flag composition are not implemented. Variation-selector handling is limited.

Simple HTML forms

Mini Browser supports simple GET forms. Supported input types include text, search, url, hidden and submit. Submit buttons made with the button element are also supported. 

[1] q:
[2] [Search]

Type 1 and press Enter to edit the field. Enter the search text and press Enter again to store it. Then type 2 and press Enter to submit.

GET form data is URL encoded. Hidden fields are submitted, disabled fields are ignored, and an activated named submit button is included where appropriate. Up to 4 forms with up to 8 fields per form are supported.

POST forms are recognised but are not submitted. Textarea, select, checkboxes, radio buttons, file uploads and JavaScript-driven forms are not currently supported.

HTML rendering

Mini Browser understands useful structure from ordinary HTML, including:

  • headings and paragraphs
  • line breaks
  • ordered and unordered lists
  • preformatted and inline code text
  • real bold and strong text
  • emphasis and italic text
  • horizontal rules
  • simple table rows and cells
  • links and simple forms
  • named and numeric HTML entities

Unordered list items use an ASCII * marker for compatibility with installations that do not include the external Unicode font.

Navigation

Links and visible form controls receive action numbers. Type an action number and press Enter to activate it.

Use Up and Down to scroll; holding an arrow gives continuous scrolling. J and K provide one-line scrolling.

Browser shortcuts

  • WHY+E - enter a new URL
  • WHY+C - edit the current URL
  • WHY+H - home
  • WHY+R - reload
  • WHY+B - back
  • WHY+G - forward
  • WHY+F - add or remove bookmark
  • WHY+M - bookmarks
  • WHY+S - capture and transmit the visible 716x716 viewport
  • WHY+Z - capture and transmit the complete rendered page
  • WHY+Q - quit

Screenshots

Mini Browser 2.4 supports two screenshot modes. WHY+S captures the visible 716x716 browser viewport. WHY+Z captures the complete rendered page, including content below the viewport. Full-page capture reuses the normal renderer as a slice-based scratch surface, so it does not allocate a giant 716xN framebuffer or change the current scroll position. Both modes use RGB24 data from the SDL renderer, lightweight RLE5 compression, per-record CRC32 and XOR forward-error correction, transmitted over USB serial.

The Mini Browser repository includes the standalone receiver badge_screenshot.py. Start it on a serial-connected macOS or Linux computer and then press WHY+S on the badge: 

./badge_screenshot.py /dev/cu.wchusbserial10

For a complete rendered page:

./badge_screenshot.py /dev/cu.wchusbserial10 --full-page

On Linux the device will commonly be something such as /dev/ttyUSB0. The receiver validates the transfer, repairs a single missing or damaged data record per FEC group where possible, verifies the complete CRC32, decodes the RLE stream and writes a PNG.

A custom firmware is not required for screenshots triggered physically with WHY+S. The screenshot-enabled Mini Browser and a USB serial connection are sufficient.

The receiver can also request the screenshot from the host: 

./badge_screenshot.py /dev/cu.wchusbserial10 --request
./badge_screenshot.py /dev/cu.wchusbserial10 --full-page --request

The --request mode requires the custom firmware because stock BadgeVMS firmware does not implement the host-to-badge serial keyboard protocol.

Optional custom firmware and automated testing

A customized WHY2025 firmware is available at github.com/mactjaap/firmware. It adds a serial keyboard bridge to the normal BadgeVMS keyboard path, allowing a macOS/Linux computer to send keyboard events to Mini Browser over USB serial.

The firmware repository includes badge_keyboard.py for interactive computer-keyboard control of the badge. This also allows browser accelerator commands such as WHY+E, WHY+H, WHY+R, WHY+B, WHY+G, WHY+F, WHY+S, WHY+Z and WHY+Q to be generated remotely.

The same repository contains automated Mini Browser test scripts. They can drive navigation, open configured websites, perform searches, exercise browser commands and automatically request and save screenshots after test steps. This provides repeatable regression testing without manually operating the badge for every page.

The custom firmware is optional for normal Mini Browser use and physical WHY+S screenshots. It is required when a host must send keyboard commands to the badge, including fully automated tests and badge_screenshot.py --request.

Bookmarks and history

Mini Browser stores up to 32 bookmarks and maintains up to 32 HTTP/HTTPS history entries. Going Back and then navigating somewhere new discards the old forward branch. Reloading does not create a duplicate history entry. 

APPS:[mini_browser]bookmarks.txt

Network behaviour

Mini Browser uses libcurl and HTTP/1.1 where available, follows redirects to a bounded limit and requests identity transfer encoding. Connection failures and HTTP errors are shown as readable browser pages.

Resource limits

  • downloaded page data - 64 KiB
  • URL - 256 bytes
  • links - 128
  • interactive actions - 160
  • forms - 4 per page
  • form fields - 8 per form
  • editable form value - 127 characters
  • bookmarks - 32
  • history entries - 32

Unsupported web features

Mini Browser does not implement JavaScript, CSS layout, images, audio/video, POST form submission, complex form controls, file uploads, a complete HTML5 DOM/parser, color emoji or complex emoji composition.

Unicode font

The tested 2.4 font asset combines unifont_jp-17.0.02.hex and unifont_upper-17.0.02.hex into unifont_cjk.bin. The generated MBCJ v1 file contains 56,352 usable glyphs across 101 ranges and is 1,804,488 bytes (about 1.72 MiB).
